# IA-TB 2.6 DEBUG — Function Registry Manager (état partiel)

**Branche de référence évolutive** `2.6`, base `2.5.3` ; import initial de `feature/2.6-function-registry`. **Version actuelle : `2.6.0-dev.1`.**

## Changement documenté
- Un manifeste `FunctionRegistry/Functions.json` et un `VERSION.json` dans chaque composant CP/1 recensé.
- Générateur Node.js `App/Tools/FunctionRegistry/generate.js` à lancer à chaque mise à jour des contrats CP/1.
- `App/Core/FunctionRegistry/manager.js` : agrégation, SQLite, cache RAM, grants par agent, révocation quand un contrat change.
- Les autorisations commencent à `DENY` ; les types et retours non établis sont `unknown`.
- Les fonctions à effet de bord ne deviennent jamais exécutables via un simple manifeste.

## Périmètre encore NON livré
- Hook d'exposition du registre dans les services Engines réels et synchronisation CP/1 push/pull en temps réel.
- Vérification au point d'exécution du Router/Engine.
- API ADMIN sécurisée et persistance d'une interface Privilèges dans la vraie page Settings.
- Qualification CI et tests end-to-end.
- Déploiement sur GEN-1 et build RELEASE.

## Exemples issus du Protocol Registry réel

`marketdata.candles` : requis `symbol`, `timeframe` ; optionnels `limit`, `exchange`, `source` etc.
`risk.gate.evaluate` : évaluation des risques ; paramètres selon contrat CP/1, aucune permission d'exécution implicite.
`trading.execute` : requis `risk_approval_id`, `exchange`, `symbol`, `side` ; **HIGH**, DENY par défaut.
`trading.account.positions` : requis `exchange` ; lecture des positions, autorisation par agent nécessaire.

Les sorties des handlers ne sont pas encore validées et les niveaux de risque sont des propositions conservatrices.

## Politique d'évolution 2.6

Les prochains patchs (2.6.0-dev.2, dev.3, etc.) se feront progressivement sur des branches dédiées créées depuis `2.6`, puis fusionnées après revue et CI. Ne pas déclarer 2.6.0 stable avant un parcours CP/1 complet, authentification ADMIN et contrôles d'exécution.

Ne jamais laisser croire que la publication des fichiers `Functions.json` active automatiquement leur synchronisation. Tous les manifestes doivent être régénérés et vérifiés à chaque modification de contrat avant l'activation de permissions.
