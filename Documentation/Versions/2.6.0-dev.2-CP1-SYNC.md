# IA-TB 2.6.0-dev.2 — CP/1 Function Registry reconciliation

**Branche candidate** `feature/2.6.0-dev.2-cp1-sync` depuis `2.6`. Aucun déploiement GEN-1 ; aucun droit de trading accordé.

## Réalisé
- `App/Core/FunctionRegistry/sync_service.js`: orchestration Core, interrogation du Router CP/1 via client existant authentifié, import de `Functions.json` versionnés localement, rafraîchissement de la DB SQLite et invalidation du cache RAM en cas de modification.
- Démarrage Core optionnel `IATB_FUNCTION_REGISTRY_SYNC_V26=1`; par défaut **désactivé** afin de protéger le runtime existant.
- Périodicité configurable via `IATB_FUNCTION_REGISTRY_INTERVAL_MS` (minimum 15 secondes).
- Fichier DB privé sous chemin absolu `IATB_FUNCTION_REGISTRY_DB`, par exemple un volume DEBUG privé ; ne jamais stocker SQLite dans Git.
- Réconciliation périodique après panne du Router sans basculer les privilèges en ALLOW.
- Test unitaire `node App/Core/FunctionRegistry/Tests/test_sync_v26.js` sur runtime Node.js 22 avec dépendances `App/node_modules` installées.

## Limites explicites

Ce jalon **n'implémente pas encore les notifications push d'une mise à jour Engine**. Le Core interroge le Router CP/1 pour vérifier sa disponibilité et lit ensuite les manifestes **installés dans son propre filesystem**, sans interroger les Engines séparés pour leurs manifestes. En déploiement Docker multi-services, un même `Functions.json` n'est pas automatiquement distribué entre les conteneurs. Le raccordement final nécessitera une route CP/1 de catalogue par Engine, des notifications versionnées et un ACK/retry durable.

Les `Functions.json` existants sont issus du Registry CP/1 déclaratif et comportent parfois des paramètres ou des sorties `unknown`. Le champ `verified_handler=false` interdit leur passage en ALLOW via `manager.grant`. Ne pas exposer de nouvelles permissions sur cette base seule.

## Suite pour une synchronisation automatique complète
1. Ajouter un adaptateur de publication/version par Engine avec registre local et outbox.
2. Ajouter une route CP/1 de récupération et une notification de changement, authentifiées côté Router ; identifier et contraindre l'Engine émetteur.
3. Core : récupérer la version et le contenu directement de chaque Engine, puis ACK ; comparer les numéros de révision et rejouer après reconnexion.
4. Vérifier le cache, les suppressions, les révisions et les permissions sur tests end-to-end isolés.
5. Ajouter les API ADMIN et la UI `Paramètres → IA → Privilèges` seulement après validation des contrôles d'exécution.

## Exécution DEBUG sans risque
```bash
cd App
npm ci --ignore-scripts
node Core/FunctionRegistry/Tests/test_sync_v26.js
```

L'installation de dépendances native de `better-sqlite3` doit être vérifiée dans l'environnement cible ; la commande ci-dessus est indicative et peut nécessiter les étapes de compilation natives ordinaires. N'activer aucune variable de sync sur GEN-1 sans recette.
