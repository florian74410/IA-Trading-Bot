## Architecture et commandes

- Réutilisation de RuntimeState, de la machine à états et de la base ADMIN P3.
  Migration JSON additive ; aucun protocole historique renuméroté.
- EMERGENCY_STOP : transaction atomique intention/état, preuve Auth21/CSRF et
  Firewall conservés, anti-rejeu persistant, aucune annulation ou liquidation.
- Contrôle final de génération et d'état au transport, partagé entre processus ;
  une opération partie reste incertaine. Shutdown préserve urgence et maintenance.
- Orchestrateur P5 : scopes serveur, propriété locale explicite, préflight et digest,
  SAFE/CLOSE distincts, confirmations distantes, quantités décimales, idempotence,
  rapprochement Portfolio et priorité P4.
- Les mutations LIVE sont bloquées dans le service, le moteur et les executors.
  Même `IATB_TRADING_LIVE=1` ne les active pas dans cette version DEV.

| Commande | Service livré | Qualification |
| --- | --- | --- |
| STATUS | État, opérations incertaines, dernière intervention, P5 du demandeur | Parcours réel Auth21/Core/Firewall/Engine |
| EMERGENCY_STOP | Opérationnelle, verrou durable | Intégration et tests négatifs |
| DRAINING_STOP | Bloque sans muter les brokers ; signale NOT_QUALIFIED | Orchestrateur SAFE/CLOSE sur fixtures |
| RECOVER | Refus explicite sans raccordement de réconciliation | Callback backend testé sur fixtures ; non installé |
| START / RESTART | COMMAND_IMPLEMENTATION_PENDING | Ne suppriment jamais le verrou |

ADMIN Maintenance réutilise le panneau existant : boutons désactivés hors READY,
confirmation d'urgence, inventaire SAFE, diagnostic de reprise, clôture désactivée,
états backend et compteur des opérations incertaines. Aucune route UI → Engine.
Le panneau complet de confirmation/exécution CLOSE réel reste à raccorder.

## Limites et critères non satisfaits

- Pas de registry de comptes/propriété broker de production ni de lectures privées
  CEX suffisantes. Voir la matrice, fondée sur le code des quatre executors.
- P5 réel et reprise non qualifiés ; pas de faux succès ni de vente SPOT implicite.
- Pas de qualification d'une topologie intégrée complète P5 + vrais processus
  Supervisor/Risk/Portfolio + brokers simulés. Les suites existantes de ces moteurs
  passent séparément. L'intégration multiprocessus mutante qualifiée concerne P4.
- Pas de panne électrique physique, reboot Linux matériel, reorg ou keeper GMX réel
  testés. SQLite FULL/WAL et les essais de crash étayent la durabilité logicielle,
  sans constituer ces essais matériels.
- Le verrou couvre les processus partageant le même profil persistant. Même UID
  et accès local administrateur ne constituent pas une isolation OS renforcée.
- Sauvegarde à froid requise pour le nouveau cycle de vie ; snapshots à chaud de
  maintenance non qualifiés. Le census conserve cette limitation explicitement.
- Recette locale XFCE/Firefox d'Overflow encore nécessaire avant stabilisation.
