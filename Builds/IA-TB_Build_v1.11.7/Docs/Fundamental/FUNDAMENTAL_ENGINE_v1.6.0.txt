IA-TB — FUNDAMENTAL ENGINE v1.6.0
=================================
Statut : FOUNDATION / INFORMATION_ONLY
Base de départ : IA-TB v1.5.3 STABLE

OBJECTIF
-------
Construire les "oreilles" du Fundamental Engine avant son cerveau d'analyse.
Cette version crée une mémoire locale structurée des sources et publications,
sans produire de score BULL/BEAR et sans influencer aucune stratégie.

ARCHITECTURE
------------
Sources -> Feeds -> Raw Items -> [futur Event Engine]

Stockage persistant unique : SQLite
  Fundamental/Data/fundamental.db

SQLite : better-sqlite3 8.7.0, installé avec le Node local de IA-TB.
Le premier démarrage après la mise à jour nécessite un accès Internet pour
récupérer ce runtime natif s'il n'est pas déjà présent.
La base active WAL, synchronous=NORMAL, foreign_keys=ON et busy_timeout=5000.

PERSISTANCE / MISES A JOUR
-------------------------
La base, le runtime SQLite local et les logs FE sont protégés des futurs
payloads UpdateManager : Fundamental/Data/**, Fundamental/node_modules/**,
Fundamental/fundamental.log et Fundamental/sqlite_install.log.
Les données utilisateur historiques restent également protégées
(config_v1.0.dat, secrets, user, logs, Parametres/** et Annexes/**).

SOURCE REGISTRY
---------------
43 sources de départ, sélectionnées pour couvrir :
MACRO, MONETARY, MARKET_RISK, REGULATION, CRYPTO_NETWORK, ADOPTION, SECURITY.

Une SOURCE n'est pas un FEED.
Exemple : Federal Reserve = source ; FOMC/press/X = feeds de la même source.
Cette séparation est un garde-fou contre le faux double comptage.

Le registre contient notamment : type, pays, priorité, grade initial,
fiabilité de base, rapidité de base, groupe d'indépendance, domaines de
compétence et feeds connus.

COLLECTE v1.6.0
---------------
Providers réellement activés : RSS/Atom officiels sélectionnés.
La collecte est séquentielle et bornée pour limiter CPU/RAM.
Les feeds sont interrogés selon leur intervalle. Les flux spécialisés de plus
forte importance passent avant les flux généraux.

Déduplication de fondation :
- unique external_id/hash au niveau du feed ;
- doublon hash/external_id supprimé entre plusieurs feeds DE LA MEME SOURCE.
Cela évite par exemple de compter deux fois une même publication FED présente
à la fois dans un flux général et un flux spécialisé.

La déduplication ENTRE SOURCES et la reconstruction d'un événement unique
seront la responsabilité du futur Event Engine. Elles ne sont PAS prétendues
comme terminées dans cette version.

RESEAUX SOCIAUX
---------------
X et Truth Social sont modélisés comme plateformes/feed, jamais comme une
source globale. Des comptes en liste blanche existent dans le registre
(FED, SEC, Donald J. Trump), mais le provider SOCIAL reste volontairement
PROVIDER_PENDING et désactivé en v1.6.0.

Une publication d'une personnalité officielle prouvera d'abord "X a déclaré
Y", et non automatiquement "Y est entré en vigueur". La confirmation légale
ou institutionnelle restera un événement distinct.

DONNEES ET SEMANTIQUE
---------------------
Trois classes sont prévues et ne doivent jamais être fusionnées :
- INFORMATION : fait/publication à confirmer et structurer ;
- PREDICTION : prévision, probabilité ou calcul ;
- REFLECTION : interprétation humaine ou IA.

IMPORTANT : raw_items contient en v1.6.0 des PUBLICATIONS BRUTES.
Une publication brute n'est PAS automatiquement un fait confirmé.

API LOCALE
----------
Service : 127.0.0.1:8015

Endpoints internes :
GET  /health
GET  /api/summary
GET  /api/sources
GET  /api/sources/:code
GET  /api/feeds
GET  /api/raw-items
GET  /api/events
GET  /api/context?q=...
POST /api/collect

Le navigateur n'accède pas directement au SQL. Depuis l'interface IA-TB,
les endpoints passent par l'API Core authentifiée /api/fundamental/*.

CHAT IA TRADING
---------------
Nouvelle permission en lecture : fundamental_read.
Lorsqu'une question du Chat Trading concerne le fondamental, les sources,
la macro, la régulation, les news ou les thèmes associés, le Core peut joindre
un contexte compact fourni par /api/context.

Le prompt rappelle explicitement que la v1.6.0 contient encore des
publications brutes. L'IA ne doit pas les transformer silencieusement en faits
confirmés. L'IA n'a aucun accès SQL direct.

PAGE /fundamental
-----------------
Page dédiée, lisible et structurée :
- synthèse compacte ;
- publications récentes ;
- couverture par domaine ;
- Sources & Qualité ;
- Flux & Collecte ;
- méthodologie / garde-fous.

La synthèse IA et les scores directionnels restent volontairement désactivés.
Aucun gros compteur Fear & Greed n'est introduit comme donnée primaire.

ADMIN / LIFECYCLE
-----------------
Fundamental Engine apparaît comme service restartable dans ADMIN.
Logs : Fundamental + Fundamental SQLite.
Le redémarrage global inclut le FE.
start.command installe/valide SQLite avant lancement du FE.

SECURITE DE DEMARRAGE : si le module SQLite ne peut pas être installé ou si
le FE ne démarre pas, IA-TB continue. Le Fundamental Engine reste OFFLINE au
lieu de bloquer le Core, le Router ou le trading existant.

LIMITES ASSUMEES v1.6.0
-----------------------
- pas d'Event Engine sémantique ;
- pas de corroboration indépendante inter-sources ;
- pas de scoring fondamental ;
- pas de BULL/BEAR ;
- pas de synthèse IA persistée ;
- pas de Social Provider actif ;
- pas d'influence sur Strategy Engine.

Ces limitations sont volontaires : la v1.6.0 pose une fondation auditée et
modulaire avant les itérations d'analyse.
