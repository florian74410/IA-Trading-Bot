IA-TB — Communication Runtime v1.7.2
====================================

OBJECTIF
-------
Préparer le système nerveux de la future v2.0 sans démarrer de Supervisor IA.

COMPOSANTS
----------
- Communication Protocol CP/1 : format commun, versionné et validé.
- Communication Router : registre, contrôle d'accès, routage, ACK et audit.
- Indicator Engine : Engine normalisé et source unique de calcul des indicateurs.
- Chart Viewer : composant visuel contrôlable, jamais un Engine.
- Chat IA Central : premier client humain du Router.

CHAT / CHART
------------
Le Chat ne doit plus considérer un texte généré par le LLM comme preuve d'exécution.
Une action Chart est planifiée par le Router, exécutée par le navigateur puis confirmée
par un ACK SUCCESS / REJECTED / ERROR. Le message final affiché à l'utilisateur est
construit à partir de cet ACK.

MULTI-STRATEGY PREP
-------------------
Un seul Strategy Engine pourra gérer plusieurs Strategy Instances légères.
Une instance possède un strategy_instance_id, un rôle (PRIMARY/HEDGE/...), un état,
un symbole/timeframe et un propriétaire Supervisor éventuel.
Une Strategy Instance ne peut appartenir qu'à un seul Supervisor actif à la fois.

MULTI-SUPERVISOR PREP
---------------------
Le protocole est compatible avec plusieurs Supervisor Instances, avec rôle, scope,
session, epoch, heartbeat, profil de ressources et Worker Thread réservé.
Pour le moment : max_active_supervisors = 1 et aucun Supervisor IA n'est lancé.

ETATS / PROTECTION
------------------
Etats préparés : ONLINE / DEGRADED / PROTECTION / OFFLINE.
Politiques préparées : PROTECT_CONTINUE / PROTECT_EXIT / PROTECT_FREEZE.
Le comportement décisionnel sera implémenté avec les futurs Supervisor/Risk/Trading Engines.

SECURITE LOCALE
---------------
- localhost uniquement
- secret inter-processus local
- whitelist de capacités
- validation stricte des arguments
- request/action IDs
- anti-replay CP
- timeout / taille bornée
- audit dans logs.dat sans exposer les secrets
