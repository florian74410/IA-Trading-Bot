IA-TB Protocol Registry v2.0 — v1.8.5

Objectif
- Repertorier tous les objets connectables au Router sans codage en dur du coeur du Router.
- Types supportes : CORE, MODULE, ENGINE, IA, VIEWER, SERVICE, FIREWALL, PROTECTION, CONNECTOR, ADDON.
- Une entree = un manifeste JSON dans Core/Communication/ProtocolRegistry/.
- Chaque entree possede une table logique de communication : commands, dataTypes, events.

Ajout d'un nouvel objet
1. Ajouter un manifeste JSON dans Core/Communication/ProtocolRegistry/.
2. Declarer id, label, type, transport et endpoint.
3. Declarer les commandes exposees et leur schema d'arguments.
4. Declarer les types de donnees produits/consommes et les evenements.
5. Pour CP/1, le service s'enregistre sur /communication/v1/register avec exactement un sous-ensemble des commandes declarees.
6. Aucune modification du coeur du Router n'est necessaire pour autoriser une nouvelle commande CP/1 correctement declaree.

Endpoints Router
- GET /communication/v1/registry : registre complet et index commandes/donnees/evenements.
- GET /communication/v1/registry/<id> : table d'un objet.
- GET /communication/v1/capabilities : vue de compatibilite + objets Protocol Registry.

Securite
- Un service inconnu du Protocol Registry est refuse.
- Une commande non declaree dans sa table est refusee.
- Les arguments CP/1 sont valides selon la table du composant.
- L'hote dynamique reste limite a 127.0.0.1.
