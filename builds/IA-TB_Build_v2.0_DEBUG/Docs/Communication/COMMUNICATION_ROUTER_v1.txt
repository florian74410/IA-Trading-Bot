TRADINGBOT — COMMUNICATION ROUTER v1
====================================
Role
----
Le Router existant sur 127.0.0.1:8000 devient egalement le Communication Router.
Aucun nouveau processus ni port n'est ajoute pour cette fonction en v1.7.

Responsabilites
---------------
- annuaire/registry des Engines ;
- decouverte des capacites et events declares ;
- health check, version, schema et latence ;
- authentification des appels internes ;
- controle d'acces et whitelist ;
- validation des schemas de commande ;
- routage transparent vers le bon Engine ;
- verification du hash de reponse ;
- audit ;
- buffer borne des events spontanes.

Le Router NE DOIT PAS
---------------------
- calculer un indicateur ;
- interpreter une analyse ;
- modifier un score ;
- resumer la reponse d'un Engine ;
- prendre une decision de trading.

Endpoints de diagnostic locaux
------------------------------
GET  /communication-health
POST /communication-test
Ces deux endpoints n'exposent pas la cle interne et ne permettent pas d'envoyer une action arbitraire.

Endpoints internes proteges CP/1
--------------------------------
POST /communication/v1/register
POST /communication/v1/request
POST /communication/v1/event
GET  /communication/v1/events
Ils exigent X-IATB-CP-Token.

Registry v1
-----------
La v1.7 autorise uniquement Indicator Engine dans le registry CP. La liste blanche sera etendue moteur par moteur lors des futures normalisations (Fundamental en v1.8, etc.).
Un Engine ne peut s'enregistrer qu'en 127.0.0.1 et uniquement avec les capacites/events autorises par le build.

Scalabilite future
------------------
Le Supervisor connait le Router, pas les ports des Engines. Le Router pourra donc plus tard pointer vers des Engines deployes sur d'autres processus/VPS sans changer le contrat logique utilise par le Supervisor.
