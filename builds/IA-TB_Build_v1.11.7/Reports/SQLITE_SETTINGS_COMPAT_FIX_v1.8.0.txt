IA-TB v1.8.0 - SQLite Settings compatibility fix
Date: 2026-08-31

Observed target error:
  NOT NULL constraint failed: settings.value_json

Cause:
  Existing user_data.db contains a legacy settings schema where value_json is
  mandatory. The v1.1 store added value_b64, then INSERT OR REPLACE populated
  only the new columns. SQLite correctly rejected the row because the existing
  value_json column is NOT NULL.

Fix in Core/Settings/sqlite_settings_store.js v1.2:
- Detect actual settings table columns with PRAGMA table_info.
- Preserve existing table; no destructive recreation.
- Migrate legacy value_json or value content to value_b64 where applicable.
- On writes, populate value_b64 plus any legacy value_json/value columns that
  remain in the database, satisfying legacy NOT NULL constraints.
- Continue populating value_type and updated_at when present.
- Read fallback supports value_b64, value_json, then value.

Safety:
- Existing user_data.db is not deleted.
- Existing settings rows are preserved.
- Runtime PID/health remains non-persistent.

Validation in build environment:
- Node syntax check: PASS.
- Live sqlite3 CLI runtime test unavailable in build container; target Mac test
  remains required.
